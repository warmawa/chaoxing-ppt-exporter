写给想读懂代码、或者打算自己改的人。按"踩过的坑"组织，而不是按文件顺序。

## 一、学习通课件到底藏在哪里

从课程章节页点开一个 PPT，浏览器的 iframe 会套好几层：

```
mooc1.chaoxing.com/mycourse/studentstudy?chapterId=...   ← 章节页
└── iframe: knowledge/cards
    └── iframe: ananas/modules/pdf/index.html            ← 课件预览器
        └── iframe: pan-yz.chaoxing.com/screen/v2/file_xxx  ← 云盘预览页
            └── 图片：s3.ananas.chaoxing.com/sv-xx/doc/../<oid>/thumb/N.png
```

关键点是**别去追 DOM 结构**。层级和 class 名会变，唯一稳定的是：

1. 最内层有 `window.fileinfo`，里面躺着真实下载地址
2. 不管怎么变，页面总得把图片请求发出去

所以工具的核心不是"解析页面"，而是**监听网络行为**。

## 二、三种策略，从好到坏

### 策略 A：原始文件直链

最内层预览页的全局变量里通常有 `download` 字段，指向老师上传的原件。
拿到它就用，画质、格式全保留，还最快。

字段名不完全固定，所以 `detector.js` 用的是**鸭子类型**而不是硬编码键名：

```js
function looksLikeFileInfo(obj) {
  const lower = new Set(Object.keys(obj).map(k => k.toLowerCase()));
  return (lower.has('objectid') && (lower.has('download') || lower.has('pagenum') || lower.has('suffix')))
      || (lower.has('download') && lower.has('suffix'))
      || (lower.has('pagenum') && lower.has('thumb'));
}
```

只要一个对象同时具备这几类字段里的组合，就认为它是文件信息。取字段时也按
常见别名列表逐个试（`objectid` / `object_id`、`download` / `downloadUrl` / `fileUrl` …）。

### 策略 B：推导 PDF 直链

超星会把文档转码成 PDF，放在和图片同一前缀下：

```
https://s3.ananas.chaoxing.com/sv-w9/doc/8f/1b/f7/<oid>/thumb/1.png
https://s3.ananas.chaoxing.com/sv-w9/doc/8f/1b/f7/<oid>/pdf/<oid>.pdf
```

看起来规律很清晰，但**目录深度是会变的**——出现过 `doc/8f/1b/f7/<oid>/` 三段式，
也出现过 `doc/ab/<oid>/` 两段式。

第一版代码写成"doc 后面跟几个十六进制段去猜"，结果测试直接挂了：

```js
// ✗ 错误写法
/^(.*\/doc\/[^\/]+\/[0-9a-f]{8,40})\//
```

它假设 `doc/` 后面只有一个目录段。碰到三段式就完全匹配不上，返回 `null`，
PDF 直链也就永远推导不出来。

而且这个问题**没法靠"多写几段"绕过去**：objectId 本身就是 32 位十六进制，
同样满足 `[0-9a-f]{2}/` 这种两两分组，正则的贪婪匹配会把 objectId 也一起吞掉。

正确的做法是换个锚点——`/thumb/<页码>.<后缀>` 永远是结尾，从后往前切：

```js
// ✓ 去掉末尾的 /thumb/N.png，剩下的就是前缀
function extractDocPrefix(url) {
  const m = /^(.*)\/thumb\/\d+\.(?:png|jpe?g|webp|gif)(?:\?.*)?$/i.exec(url);
  return m ? m[1] : null;
}

// objectId 就是前缀的最后一段
function extractObjectId(url) {
  const prefix = extractDocPrefix(url);
  if (prefix) {
    const m = /\/([0-9a-f]{8,40})$/i.exec(prefix);
    if (m) return m[1];
  }
  const m2 = /\/([0-9a-f]{16,40})(?:\/|\.|$)/i.exec(url);
  return m2 ? m2[1] : null;
}
```

这个教训是：**结构不确定时，认结尾不认开头**。这条在 `test/detector.test.cjs`
里有对应用例，改这段正则前先跑测试。

### 策略 C：逐页图片自己合成

前两条都拿不到时才走这条路：把所有 `thumb/N.png` 抓下来，合成 PDF。

页码规律是从已加载的图片里聚类出来的——按"前缀"分组，取最大页码作为总页数，
中间缺的页按同样规律补上 URL。

## 三、图片请求监听（为什么不用 MutationObserver 硬扫 DOM）

懒加载的图片，DOM 里可能挂着 `data-src`、`data-original`、`data-echo`……名字是随机的，
而且图片节点可能是被 JS 动态插进来的，扫 DOM 总会有漏。

换个思路：**图片要显示，就一定要设置 `src`（或走 fetch/XHR 拿 blob）**。
所以在页面自己的脚本跑起来之前（`run_at: document_start`），先把这几个口子堵上：

```js
// 劫持 src 的 setter
const desc = Object.getOwnPropertyDescriptor(HTMLImageElement.prototype, 'src');
Object.defineProperty(HTMLImageElement.prototype, 'src', {
  get: desc.get,
  set(value) { record(value); return desc.set.call(this, value); },
});
// 再顺手加上 fetch 和 XHR.open
```

这样只要图片加载过，URL 就一定进了记录集合。

在油猴版本里，这些 hook 必须打在 `unsafeWindow` 上——Tampermonkey 的沙箱里
直接改 `HTMLImageElement.prototype` 影响不到页面自己的代码。

配合 `autoScroll()` 主动把课件滚一遍，就能把懒加载的页面全部骗出来。
滚动的终止条件是"连续三轮没有新图片出现"，比"滚够 N 次"更稳。

## 四、多层 iframe 与去重

`content_scripts` 配了 `all_frames: true`，每个 frame 都会注入一份。
好处是总有一份能摸到课件，坏处是**四层 iframe 可能弹四个面板**。

处理办法是把去重交给 background：每个 frame 探测到课件后先问一句
"这个课件有人认领了吗"，只有第一个拿到 `first: true` 的才建面板。

```js
// content.js
const first = await chrome.runtime.sendMessage({ type: 'cx:register-deck', deckId: deck.id });
if (!first || !first.first) return;
```

用 `chrome.storage.session` 存认领记录，标签页关闭时清掉。

## 五、PDF 生成器的坑

不引入 jsPDF 是有意的：只需要"把 JPEG 塞进 PDF"这一个能力，自己写 200 行
换掉几百 KB 的依赖，顺带没有供应链风险。

### 坑 1：xref 的字节偏移

PDF 尾部的 `xref` 表记录每个对象在文件中的**绝对字节偏移**。算错一个字节，
Acrobat 这类严格实现会直接拒绝打开；而 Chrome 内置阅读器往往还能显示，
所以本地随手一测根本发现不了。

因此在写字节之前就得登记偏移，而不是事后补：

```js
const beginObj = (id) => { offsets[id] = offset; };  // 在 push 之前调用
```

`test/verify-pdf.py` 会逐条核对"xref 里记的偏移处，是不是真的写着 `<id> 0 obj`"。

### 坑 2：二进制标记被编码坏了

PDF 头上那行 `%âãÏÓ` 是给编辑器看的"这是二进制文件"标记，必须是原始字节
`0xE2 0xE3 0xCF 0xD3`。

但如果写成 JS 字符串 `'%\xe2\xe3\xcf\xd3\n'` 再交给 `TextEncoder`，
它会把每个字符按 **UTF-8** 编码——`\xe2` 会变成两字节 `C3 A2`，原字节就没了。

```js
// ✗ TextEncoder 会把 \xe2 编成 C3 A2
push('%\xe2\xe3\xcf\xd3\n');
// ✓ 按原始字节写
push(new Uint8Array([0x25, 0xe2, 0xe3, 0xcf, 0xd3, 0x0a]));
```

### 坑 3：中文标题乱码

PDF 的字面量字符串 `(...)` 只认单字节编码，中文塞进去必然乱码。
规范给的解法是改用 **UTF-16BE + BOM** 的十六进制串：

```
/Title <FEFF7B2C4E007AE0>     ← "第一章"
```

`pdfText()` 会按内容自动挑写法：纯 ASCII 用 `(...)`，含非 ASCII 就转 `<FEFF...>`，
超过 BMP 的字符还要拆成代理对。

### 坑 4：PNG 的透明通道变黑块

超星返回的原图常常是 PNG，带 alpha 通道。PDF 的 `/DeviceRGB` 图片没有透明概念，
直接嵌进去，透明区域会显示成黑色一团。

所以转 JPEG 时先铺一层白底：

```js
ctx.fillStyle = '#ffffff';
ctx.fillRect(0, 0, width, height);   // 先铺白
ctx.drawImage(bitmap, 0, 0, width, height);  // 再画图
```

顺带这一步也解决了体积问题：同一张幻灯片，PNG 转 JPEG 能省 5%~30%。

## 六、Referer 与 403

云盘的下载接口会校验请求来源，Referer 不对就返回 403。

解决办法不是去伪造请求头（`Referer` 是浏览器禁止脚本修改的头部），
而是**让浏览器自己发请求**——在页面里创建一个 `<a>` 点一下，
Cookie、Referer、UA 全自动带对：

```js
const a = document.createElement('a');
a.href = url;
a.target = '_blank';
document.body.appendChild(a);
a.click();
a.remove();
```

对于必须由扩展代劳的图片请求（策略 C），走 `declarativeNetRequest` 的
**会话级规则**临时补 Referer，用完立刻删掉，不污染全局：

```js
await chrome.declarativeNetRequest.updateSessionRules({
  removeRuleIds: [RULE_ID],
  addRules: [{
    id: RULE_ID,
    action: { type: 'modifyHeaders', requestHeaders: [
      { header: 'Referer', operation: 'set', value: referer }] },
    condition: { regexFilter: '^' + escapeRegex(url) + '$', resourceTypes: ['xmlhttprequest', 'image'] },
  }],
});
```

## 七、MV3 为什么需要 offscreen document

MV3 的 service worker 里**没有 DOM**，拿不到 `canvas`，也就没法把 PNG 转成 JPEG。

所以流程是：

```
content.js ──消息──> background.js ──创建/复用──> offscreen document
                          ↑                            │
                          └────── 进度回传 ─────────────┘
```

offscreen document 属于扩展上下文，天然享有 `host_permissions`，
跨域取图不受 CORS 限制——这是它比 content script 更适合干这活的原因
（content script 的 fetch 用的是页面 origin，会被 CORS 挡下来）。

任务完成后延迟 20 秒再关闭，避免连续导出时反复创建。

## 八、调试技巧

**看探测结果**：在课件页面按 F12，控制台执行

```js
CXDetector.detect()
```

**看看图片都被抓到没有**：

```js
[...window.__cxImageUrls]
```

**检查 PDF 直链推导**：

```js
const d = CXDetector.detect();
console.log(d.objectId, d.pdfUrl, d.downloadUrl, d.strategy);
```

如果 `strategy` 是 `images` 但你知道服务器上有原文件，多半是 `fileinfo` 的
字段名又变了——把 `window.fileinfo` 打出来对照 `detector.js` 里的别名列表加一条。

**验证生成的 PDF**：

```bash
python test/verify-pdf.py test/output/sample.pdf
```
